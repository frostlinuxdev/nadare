# DW-Proton 11.0-16 as the pinned runner (2026-11-13)

Released upstream 2026-10-31 (dawn-winery/dwproton-mirror). Pinned after these checks.

**Integrity.** The project's published `dwproton-11.0-16-x86_64.sha512sum` verifies the download, and the
computed sha256 equals GitHub's asset digest: `657b0e66efb0a9824215bc0887a68f758355517cc4eaab3164c019bb6cb95268`
(339,558,796 bytes).

**What it is.** Same Wine base as 11.0-15 (`wine-11.0 (CachyOS)`) and the same DXVK (`v3.1.1-97`), so the
Arknights present-timing workaround question is unchanged from 11.0-15.

**Real GPU, headless (AMD Ryzen 3500U / Vega 8, RADV, Debian 13, `gamescope --backend headless -W 1280 -H 720`).**
Each game was installed by Nadare 0.1.0b24 (internal build) into a fresh home, then launched and measured after
150 s: the game process's CPU over 10 s and the average `gpu_busy_percent` over the same 10 s (a game frozen on its
first frame sits near 1% CPU). 11.0-15 runs are the same games, same prefixes, runner switched back.

| Game | 11.0-16 | 11.0-15 |
|---|---|---|
| Stella Sora (`StellaSora.exe`) | 188% CPU, GPU 70% busy (repeat run: 189%, 70%) | 181% CPU, GPU 71% busy |
| Arknights, default (`dxvk.enablePresentTiming = False`) | 39% CPU, GPU 23% busy | 38% CPU, GPU 22% busy |
| Arknights, workaround off (`DXVK_CONFIG=""`) | 39% CPU, GPU 21% busy | not run |
| Chaos Zero Nightmare | install, WebView2 and VC++ setup in the prefix OK; signed in (QR) and launched: shipped PCSDK stub started, game process 76% CPU, GPU 19% busy | not run |

All three draw past their first frame on 11.0-16, with the same load as on 11.0-15.

**Arknights keeps its workaround.** The present-timing hang (2026-10-15-arknights-wayland-dxvk.md) was seen on
NVIDIA under KWin Wayland; headless gamescope on AMD runs fine with or without the workaround on both runners, so
this test cannot show that the workaround may go.

**Not covered.** NVIDIA and a real Wayland compositor (KWin): the maintainer's desktop. Screenshots: headless
gamescope's Xwayland root cannot be captured, so the "changed pixels" measure was not available; CPU and GPU busy
were used instead. CZN ran with `WineD3D on OpenGL` on this GPU (its renderer choice on Vega 8), not DXVK.
A fresh clean-VM install.

**Mechanics.** The pin lives in `core/runners.RUNNERS["dwproton"].tested`. Profiles that name `dwproton` (or
nothing, on CZN/Arknights/Stella Sora, the catalog games and the generic Wine/Proton games) get 11.0-16,
downloaded once (324 MB) if absent; profiles with an explicit runner path are unchanged.
